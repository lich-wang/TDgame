# 霍尔木兹狂想曲 UI/UX 重构方案

## 目标

把当前可玩的 Canvas 原型升级成更有完成度的战术指挥台体验，同时保留现有纯静态资源结构，确保推送到 GitHub 后可由 Cloudflare Worker `game` 自动部署。

## 范围

- 重构开始画面，使首屏具备游戏主题、局势信息和明确行动入口。
- 使用真实位图资产替代纯 CSS 氛围背景，至少包含一张首屏背景图和一张战场底图。
- 将玩家建筑、敌方船舶/飞机/登陆兵、弹头/无人机/水雷全部改为 PNG spritesheet 绘制，并让色彩、光影和视角接近 `battlefield-hormuz.png` 的半写实战场图。
- 玩家建筑 spritesheet 必须重新生成或重绘，不能复用上一版 flat/vector 程序绘制建筑。
- 将可放置塔位、水雷槽位和敌方航道重配到 `battlefield-hormuz.png` 的视觉平台和发光水道上；塔位必须落在背景图可见混凝土/金属阵地中心，不得为了排版排成直线。
- 移除原型阶段的重度 Canvas 覆盖绘制：不再额外画大面积天空、沙滩、旗帜、基地牌、粗航道高亮和方向箭头，只保留背景图、低透明交互提示和必要兜底。
- 将“水雷塔”重构为“布雷艇”：玩家在水道槽位下达布雷任务，布雷艇从波斯港/近岸出航，沿航道移动并按节奏投放水雷。
- 布雷艇是可被攻击的战场实体，有生命值、移动状态、布雷进度和死亡状态；敌方水面舰艇进入攻击距离后会优先攻击附近布雷艇。
- 重构顶部 HUD，使波次、绿纸、油轮、声望更易扫描。
- 增加战况状态条，展示当前态势、波次进度和当前选中设施。
- 优化底部塔/主动出击按钮，提升移动端可点性和禁用状态可读性。
- 优化 Canvas 内反馈：放置预览、水雷槽位、塔位、波次进度提示。
- 修复影响体验的交互问题：布雷艇部署槽无法直接下达、竖屏旋转坐标映射错误。
- 增加 GitHub Actions 自动部署到 Cloudflare Worker `game`。

## 非目标

- 不引入前端框架或构建工具。
- 不重写核心战斗数值。
- 不迁移到 Cloudflare Pages。
- 不提交 `.env` 或任何 secret。

## 设计原则

- 第一屏直接是游戏入口，不做营销页。
- UI 应像“战术指挥台”，信息密度高但不压迫。
- 操作状态必须清楚：当前选了什么、哪里能放、钱够不够、波次处于什么阶段。
- 移动端优先保证可玩性，竖屏自动旋转后点击坐标必须准确。
- 颜色不做单一色调，主色为深海蓝、金色、警戒红、雷达绿混合使用。

## 验收标准

- `index.html` 首屏不再依赖内联段落样式，开始画面包含标题、状态摘要和主按钮。
- `assets/` 下存在可部署的真实图片资产，首屏背景图由 CSS 引用，战场底图由 Canvas 预加载并绘制。
- 图片资产不得只留在本机生成目录，必须保存进仓库并随 Worker 静态资源部署。
- `assets/sprites/` 下存在建筑、敌人、弹头三类 PNG spritesheet，并由 Canvas `drawImage()` 消费。
- 建筑 spritesheet 不再使用扁平图标风格；炮台、雷达、防空、导弹阵地应像放在背景岸防平台上的小型半写实设施，并保留透明背景。
- 塔位坐标不得使用旧直线坐标；每个塔位必须对应背景图中已有的岸防平台/混凝土阵地，放置后建筑主体不能压到海面。
- 每个塔位需要区分点击中心和建筑绘制锚点：点击中心覆盖背景平台，`drawX/drawY/scale` 负责把不同 sprites 的视觉重心压到平台上。
- 岸防炮、导弹阵地、防空阵地必须根据目标方向转向；弹药 sprites 必须按自身源图朝向修正后再旋转。
- 水雷按钮显示为布雷艇，战场中显示移动布雷艇和被投放的水雷，而不是静态水雷塔建筑。
- 敌方水面舰艇可攻击布雷艇；布雷艇被击毁后释放槽位并停止继续布雷。
- `map.js` 在背景图加载成功时不得再绘制粗航道光带、方向箭头、旗帜、基地牌等额外 UI 绘制；航道和放置点仅以低透明提示辅助交互。
- HUD 的 `wave-info`、`money-display`、`oil-ship-count`、`rep-display` 仍由 `updateUI()` 正常刷新。
- 新增的 `condition-display`、`selected-display`、`wave-progress` 在游戏运行中有实际状态更新。
- 选择布雷艇后点击蓝色水道槽位可以派出布雷艇，并占用对应水雷槽。
- 未选择塔时点击空塔位仍可自动选择一个可负担设施。
- 竖屏旋转模式下，坐标映射使用实际 canvas 尺寸，不把 y 坐标映射到不可见的 `MAP.HEIGHT=600` 区域。
- 塔位坐标落在背景图上方岸防平台附近；敌人航道沿背景图中部发光水道；水雷槽位沿同一航道分布。
- 所有 JS 文件通过语法检查。
- 新增静态结构测试覆盖关键 DOM id、脚本加载顺序、CSS 选择器和部署配置。
- GitHub push 到 `main` 后触发 workflow，workflow 成功后部署 Worker `game`。
- 编码完成后必须用 Playwright 截图验证桌面和移动视口，确认 sprites 与背景图对齐。

## 背景匹配坐标

基于 `battlefield-hormuz.png` 缩放到 `960x480` 后的视觉内容：

- 岸防平台沿海岸线错落分布，塔位使用 11 个贴合背景平台的配置对象。每个对象必须包含 `x/y` 点击中心、`drawX/drawY` 建筑锚点和 `scale`：
  `(28,176)`, `(84,165)`, `(155,150)`, `(246,132)`, `(348,120)`, `(442,110)`, `(535,100)`, `(636,88)`, `(734,78)`, `(835,74)`, `(915,72)`。
- 这些坐标分别对应背景图上 11 个已有岸防阵地；代码不得把它们当作均分排布的直线点。
- 敌方主航道沿中部发光水道从右上到左下：
  `PATH_START=(980,170)`, `PATH_END=(-60,382)`。
- 油轮反向沿同一水道偏下方通行，保留与敌舰碰撞的可读距离。
- 水雷槽沿主航道 12% 到 88% 分布，视觉上落在发光浮标线附近。

## 布雷艇玩法

- 入口：底部原“铁罐头/水雷”按钮改为“布雷艇”，仍使用 `mine` 类型键以控制改动范围。
- 部署：点击蓝色水道槽位后生成 `Minelayer` 实体，槽位进入占用状态。
- 航线：布雷艇从槽位附近偏下方进入水道，沿敌方航道方向小范围巡航，视觉上贴着背景发光水道移动。
- 布雷：布雷艇每隔固定时间在自身后方/附近投放一枚水雷，最多投放当前等级允许数量。水雷继续沿用现有触碰/磁性触发逻辑。
- 生存：布雷艇有 `hp/maxHp`、受击闪烁和血条。敌方非空中单位在射程内会对它开火或直接造成冷却伤害。
- 摧毁：布雷艇死亡后停止移动和布雷，已有水雷保留，部署槽位释放，玩家可重新派艇。
- UI：悬停布雷艇显示生命值与已布雷数量；战况条显示“布雷艇出航/布雷中/遭攻击/被击毁”等短状态。

## 部署方案

项目不是 Cloudflare Pages，而是 Cloudflare Worker `game`。自动部署采用 GitHub Actions：

- 触发：push 到 `main`、手动 `workflow_dispatch`。
- 检查：Node 语法检查、静态结构测试。
- 部署：`wrangler deploy` 到 Worker `game`。
- 必需 GitHub Secrets：
  - `CLOUDFLARE_ACCOUNT_ID`
  - `CLOUDFLARE_API_TOKEN`

## 风险

- 当前仓库是 `/home/linux/TD/game`，外层 `/home/linux/TD` 也有 Git 仓库和 `.env`，后续提交必须固定在内层仓库。
- 当前 token 能部署 Worker，但查 zone routes/DNS 权限不足；自动部署不依赖 route 查询。
- GitHub Actions 首次运行可能因 secrets 未设置失败，需要先同步本地 `.env` 中的 secret 到 GitHub 仓库。
- 生成图片可能包含不准确文字或水印，因此项目图片提示词要求无文字、无 logo、无水印；界面文字仍由 HTML/Canvas 绘制。
